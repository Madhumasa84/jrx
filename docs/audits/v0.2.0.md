# v0.2.0 launch audit

## Baseline at `505a289`

| Area | Existing behavior | Gap to close |
| --- | --- | --- |
| Signed evidence | Replay copied the baseline signing settings and cleared the private key path before checking the captured hash chain. A private-key-only test deleted the producer key before replay. | Replay omitted the public verification key and signature requirement. Constructing an Ed25519 verifier also generated a private key. |
| Transitions | The Markdown report counted all six changes. The compact status and optional gate counted new ALLOWs. | Expose HOLD → REVIEW on the status and add a limit covering all three relaxations. |
| Policy input | The impact reader read at most 1 MiB plus one byte. The YAML loader already rejected the extra byte and duplicate keys. Lint reported unknown fields. | Make the byte limit explicit at file read time and exercise both file positions with bounded, value-free failures. |
| Input and output isolation | The proposed configuration went through literal validation. Existing CLI tests checked a full private action string in combined output. | Observe candidate-driven file and socket operations and check stdout, stderr and GitHub output with a substring canary on each outcome. |
| GitHub jobs | A SHA-pinned checkout and a merge-parent check read policy blobs without checking out the proposed tree. | Separate detection from the evidence environment. Pin both trusted checkouts to the workflow SHA, reject executable modes, and distinguish missing and stale refs. |

`make lint` passed. All 24 golden policy cases passed. The first sandboxed `make test` run had 905 passes, 22 failures and 10 skips. Broker, dashboard and TLS tests encountered restricted sockets. A host rerun exercised those interfaces and Docker. The host rerun passed 936 tests with one opt-in live broker test skipped and four warnings from tests of the Gitleaks fallback.
