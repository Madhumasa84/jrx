## Findings and final verification

### Confirmed fixes

- Executable command/argv context survives compaction when unrelated tool input is
  large. Secret-scanner failures mark evaluation as degraded even with semantic
  evaluation disabled, so enforce mode blocks execution.
- Central review/enforce modes retain their execution requirements when merging
  local policies. A local mode cannot enable a HOLD override or bypass central review.
- Destructive Git checks recognize global options, combined short flags, long force
  flags, forced refspecs, and interactive rebase flags. Git's `--` option terminator
  distinguishes flag names used as arguments. Recursive `rm` options after a target
  remain detectable.
- CLI commands terminate remaining owned process-group members after completion,
  timeouts, SIGTERM, and unexpected exceptions. SIGTERM handlers are restored.
  A session stopped during network setup launches no command and cleans its egress
  resources without attempting to remove a container that was never started.
- MCP upstreams run in isolated process groups. Timeouts, session stops, gateway
  EOF, and interrupted input stop descendants that ignore SIGTERM. Regression tests
  reproduced a shutdown hang caused by a descendant retaining the upstream pipe.
- Audit replay and dashboard rendering consume the same captured log bytes that
  were verified. Policy identities bind the complete effective configuration.
  Simulation rejects changes that cannot be reconstructed from recorded decision
  inputs, including transitions involving majority aggregation.
- Workspace handoffs retain checkpoints when file metadata is incomplete and handle
  native-provider delivery without an uninitialized stream view. Hook removal keeps
  unrelated commands in the same provider event. Provider process teardown escalates
  through the group after its leader exits. Antigravity WAITING events represent an
  approval request.
- The Cosign stub is replaced by local detached signing and offline pinned-key
  verification for policy files, protected bootstrap loading, and audit entries.
  Signing runs without public transparency-log uploads and uses private temporary
  directories, bounded subprocess waits, and generic failure diagnostics. Tests
  cover tampering, wrong keys, malformed signatures, empty/binary payloads, missing
  binaries/keys, timeouts, and authentication of the captured policy bytes.
- Docker build context excludes credentials and local runtime state. Release steps
  use the published image digest for signing and SBOM attestation, configure QEMU,
  and build/validate wheel and source distributions before attaching release assets.
  No release was published during this work.
- The Python base image inherited vulnerable versions of pip and setuptools.
  Both Docker build stages now install the tested patched versions (pip 26.2.1,
  setuptools 84.0.0); the isolated wheel environment was upgraded likewise.

## Feature follow-up — 2026-10-09

The requested additions were implemented sequentially, with focused verification
after each feature:

1. `jrx policy lint`: offline diagnostics for unknown nested fields, duplicate YAML
   keys, invalid configuration, built-in signal names, conflicting threshold aliases,
   duplicate MCP authorization rules, and ineffective controls. `--strict` fails on
   warnings, and `--json` supports CI. The linter does not activate a policy or fetch
   keys, credentials, or remote policies. Custom evaluator signal names are reported
   as incompatible with the built-in evaluator. Files are limited to 1 MiB.
2. `jrx audit report`: aggregate decisions, degraded evaluations, overrides, checks,
   and policy versions from a captured snapshot after verifying its complete chain.
   Configured or explicit pinned keys verify signatures. Inclusive UTC date filters
   apply after integrity verification; action text, identities, and justifications
   are excluded. Invalid or missing logs produce no report. The input limit is
   128 MiB, and independently trusted checkpoints are still needed to detect loss
   of a valid trailing segment. Nonstandard check labels are grouped as `other`.
3. `jrx session list`: bounded pagination and active/stopped/expired/exhausted
   filters under the existing administrator authorization. Status also includes
   remaining budgets, limit reasons, and separate permissions for single tool and
   semantic reservations. Estimates describe current configured limits and are not
   billing or an execution authorization. Listing does not consume or reset budgets.

## Complete verification and corrections — 2026-10-09

The requested additional verification reproduced ten failing regression cases
before applying fixes:

- Audit reports used Unicode-aware `splitlines()` although the verifier frames
  records with newline characters. Valid JSON containing U+0085, U+2028, or U+2029
  therefore passed integrity verification and then failed during reporting.
  Reporting now uses the verifier's newline framing over the captured snapshot.
- UTC conversion of extreme ISO timestamps raised an uncaught `OverflowError`.
  It now returns the normal invalid-date error and CLI exit code 2.
- Session pagination accepted offsets outside SQLite's signed 64-bit integer range,
  causing an uncaught conversion error. Both the store and CLI reject those offsets
  before reading the database; session accounting remains unchanged.
- YAML merge flattening hid duplicate keys in merged source mappings, including
  repeated merge directives. The linter now validates the original node graph
  before constructing mappings. It preserves valid explicit merge overrides and
  aliases, rejects cycles, and bounds expanded alias work before merge processing.
- The README incorrectly described broker clock-skew detection as unimplemented.
  It now describes the existing response validation and boundary tests.
